# E-Commerce Customer Churn Prediction

## 1. Project Overview

This is an individual mini-project for AI & DS II that predicts whether an e-commerce customer is likely to churn (stop using the platform) based on their behavior and profile data.

The project covers the full ML pipeline — data preprocessing, exploratory data analysis, model training, evaluation, and a Streamlit web application for live predictions.

---

## 2. Objective

To build a machine learning model that classifies customers as **churned (1)** or **not churned (0)** using historical e-commerce data, and to deploy it as a simple interactive web application.

---

## 5. Machine Learning Models

- **Logistic Regression** — A simple, interpretable linear classifier used as a baseline model.
- **Random Forest Classifier** — An ensemble model that builds multiple decision trees and combines their results for better accuracy.

---

## 6. Data Preprocessing

Steps performed in `train.py`:

1. **Load data** from the `E Comm` sheet of the Excel file
2. **Drop `CustomerID`** — it is only a row identifier with no predictive value
3. **Handle missing values:**
   - Numerical columns → filled with **median**
   - Categorical columns → filled with **mode**
4. **Save cleaned dataset** — saved as `data/cleaned_dataset.csv` (5630 rows, 19 columns, 0 missing values)
5. **One-Hot Encoding** — categorical columns converted to numeric using `pd.get_dummies(drop_first=True)`
6. **Train-Test Split** — 80% training, 20% testing with `stratify=y` to preserve the churn class ratio

## 7. Exploratory Data Analysis

The EDA notebook is located at `notebooks/EDA.ipynb` and covers:

- **Churn Distribution** — class imbalance (~83% No Churn, ~17% Churn)
- **Numerical Feature Analysis** — histograms for Tenure, SatisfactionScore, DaySinceLastOrder, CashbackAmount, OrderCount
- **Categorical Feature Analysis** — count plots for PreferredLoginDevice, PreferredPaymentMode, PreferedOrderCat, Gender, MaritalStatus
- **Churn vs Important Features** — relationship between Churn and Complain, Tenure, SatisfactionScore, DaySinceLastOrder, PreferedOrderCat
- **Correlation Heatmap** — correlation between all numerical features

---

## 8. Model Evaluation

Both models were evaluated on the 20% test set using the following metrics:

| Metric | Logistic Regression | Random Forest |
|---|---|---|
| Accuracy | 0.8881 | 0.9831 |
| Precision | 0.7388 | 0.9942 |
| Recall | 0.5211 | 0.9053 |
| F1-Score | 0.6111 | 0.9477 |
| ROC-AUC | 0.8860 | 0.9991 |

Confusion matrices for both models are saved in the `models/` folder.

**Random Forest significantly outperforms Logistic Regression** across all metrics and is used in the Streamlit application.

---

## 9. Streamlit Application

The web application (`app.py`) allows a user to enter customer details through a simple form and get an instant prediction.

**Output displayed:**
- **Churn Prediction** — Yes or No
- **Churn Probability** — percentage likelihood of churn
- **Risk Level** — 🟢 Low (< 30%) / 🟡 Medium (30–60%) / 🔴 High (> 60%)

## 10. How to Run

**Step 1 — Install dependencies**
```bash
pip install -r requirements.txt
```

**Step 2 — Train the models**
```bash
python train.py
```

**Step 3 — Launch the Streamlit app**
```bash
python -m streamlit run app.py
```

**Step 4 — Run the EDA notebook** *(optional)*
```bash
jupyter notebook notebooks/EDA.ipynb
```
